# 图集 · SherlockGy

静态图片图集阅读器，部署在 <https://sherlockgy.github.io/>。

- 按月份归档，或按多层系列整理；支持名称、说明和标签搜索。
- 支持逐页、连续和文档阅读，以及全屏放映、缩放、原图查看和页码分享。
- 可在网页中添加、编辑、排序图集，管理系列，并导出 PDF / PPTX。
- 图片与目录保存在 GitHub；Cloudflare Worker 处理写入，GitHub Actions 构建并发布网站。

## 维护规范

### 内容边界

- 图集内容统一维护在 `data/albums.json` 和 `images/`。理解图片所需的背景、角色设定摘要、状态含义等，写入图集 `description`；图片路径及顺序以 `images` 数组为准，不在说明中重复罗列。
- 不随图片导入另建角色设定、创作过程、提示词等正文 Markdown。确需长期维护独立正文时，先确认归属和展示方式，不默认扩展图集仓库的职责。
- 说明按纯文本显示，不解析 Markdown，也不自动读取同目录的 `.md`。不要写没有实际阅读入口的“全文见某文件”，或保留本机路径、临时目录和不存在的文件引用。
- 来源、署名、许可和必要的文件对应记录可以随图保留，例如简短 `README.md`、`sources.json` 或许可证文件。这类资料用于追溯来源与使用条件，不作为另建正文的先例；读者需要看到的署名和限制也应放入图集说明。可参考[现有来源记录](images/series/ai-anthropomorphic-20261106/README.md)，不要把未核实的许可写成已获授权。
- 仓库和原图公开可访问。构建会完整复制 `images/`，其中的附属文件也会发布，即使没有网页入口；不要放入私密内容、凭据或仅供本地使用的材料。

### 修改与提交

- 修改前读取最新内容，只更新本次目标，保留其他图集、系列顺序和无关字段。出现并发变化时重新核对，不用旧快照覆盖新内容。
- 保持已有图集 ID 和未修改图片的地址稳定；只改说明不重传图片。新增图片与目录记录应一起提交，核对文件存在、尺寸准确、封面和阅读顺序正确。
- 只提交原图和维护所需的源文件，不提交 `_site/`、`.cache/`，不把构建生成的缩略图或 `thumbnails` 字段写回源目录。
- 每次提交围绕明确目的，检查完整差异，不混入无关文件、批量格式化或草稿；提交说明写清改动及验证情况。

## 内容格式

月份图集的图片放在 `images/YYYY/MM/<album-id>/`，系列图集放在 `images/series/<album-id>/`。在 `data/albums.json` 中登记：

```json
{
  "schemaVersion": 1,
  "albums": [
    {
      "id": "my-first-album",
      "title": "我的第一份知识图集",
      "date": "2026-09-15",
      "description": "主题与出处，可留空",
      "tags": ["学习笔记"],
      "images": [
        {
          "src": "./images/2026/09/my-first-album/001.png",
          "alt": "图片内容的简要说明",
          "width": 1600,
          "height": 2200
        }
      ]
    }
  ]
}
```

- 图集和系列的 `id` 均为 1–100 个字符，仅使用英文字母、数字、下划线或连字符，分别在各自列表内唯一。月份图集的 `date` 为真实的 `YYYY-MM-DD`，按字面日期归档，不做时区换算。
- `images` 数组决定阅读顺序，首张为封面；建议填写原始宽高。系统不读取 EXIF 重排。
- 顶层可增加 `series` 数组：每项包含 `id`、`title`、`parentId`；顶层 `parentId` 为空字符串，下级指向上级 ID。最多 200 个系列，不得循环引用。
- 图集用 `seriesId` 指向所属系列，无需 `date`，不进入月份归档。同级系列和同系列图集各按数组中的相对顺序展示，子系列先于直属图集。
- 文档图集可增加 `document: { "type": "document", "contentBounds": [0, 0, 1, 1] }`，默认连续阅读。边界为所有页面共用的归一化坐标 `[left, top, right, bottom]`：四项均须为 0–1 之间的有限数值，宽度 `right - left` 和高度 `bottom - top` 均至少为 0.25；缺失或无效时回退为完整页面 `[0, 0, 1, 1]`。缩减留白前核对全部页面，不改原图，也不按图片比例自动判定文档。

## 网页管理

- 从月份归档或当前系列入口添加图集。月份图集按表单日期归档，新草稿默认浏览器当天，不继承筛选月份；未配置上传服务时只能本地预览。编辑已有图集可改名称、说明、新增、排序或换图，一次保存生效，只有新增或替换的图片会上传。
- 上传和编辑时可选择“普通图集 / 文档阅读”。已有文档仅改名称、说明或图片会保留裁边；切回普通图集并保存后，文档设置及裁边会被清除，之后再切回文档阅读使用完整页面，不恢复旧裁边。
- 名称为 1–120 字，说明最多 10000 字。支持 JPG、PNG、WebP、GIF、AVIF；每个图集最多 60 张，网页上传单张最多 10 MiB、本次文件合计最多 600 MiB。
- 系列菜单支持新建子系列、重命名和移动，“调整顺序”仅整理当前层级。月份图集与系列图集不能通过网页或系列整理接口互相转换。
- 说明可展开和复制；全文为一个网址时可直接打开。下载 PDF / PPTX 使用现有上传口令，在浏览器生成，不写入仓库，也不改变原图的公开访问属性。
- 排序会改变封面或页码分享链接指向的图片。换图使用新地址，旧文件暂时保留；网页编辑不删除旧图或清理 Git 历史。
- 关闭未保存窗口会提示放弃，刷新页面会丢失草稿。保存冲突时先核对最新内容；超时后先确认仓库是否已提交，再从原页面重试，避免重复创建。
- “已保存”表示 GitHub 提交完成，网站仍需等待 Pages 发布。

## 本地运行与检查

静态预览无需安装依赖，在仓库根目录执行：

```sh
python3 -m http.server 8080
```

访问 <http://localhost:8080>，不要直接双击 HTML。Worker 仅允许正式站点的浏览器来源，本地预览不具备线上编辑权限。`tests/responsive.html` 可检查 390 px 和 320 px 布局。

Node 20+、Python 3.10+ 可运行测试与构建：

```sh
python3 -m pip install -r scripts/requirements.txt
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/build_site.py
python3 -m http.server 8080 --directory _site
```

代码或内容数据变更应运行两组测试并检查相关预览；涉及图片或构建时执行完整构建，核对说明、封面、顺序和阅读效果。仅改文档时核对文字与实现、链接和命令。报告未运行或受阻的检查，不把局部通过当作完整验证。

## 发布与配置

### GitHub Pages

Pages 的发布来源设为 **GitHub Actions**。[工作流](.github/workflows/pages.yml) 对 `master` 的 push、面向 `master` 的 PR 和手动触发执行测试与构建；PR 不部署，主分支构建成功后才发布 `_site`。

构建为本地图片生成 480 / 960 像素 WebP 缩略图，阅读和下载仍使用原图。缩略图及补充后的目录只进入发布产物，不写回源码。提交后检查对应 Actions 的构建与部署结果，不能把提交成功当作已发布。

### Cloudflare Worker

`config.js` 保存公开服务地址；`worker/worker.js` 需单独部署到 Cloudflare，并按[部署说明](worker/SETUP.md)配置 Secret。GitHub 凭据只能存入 Worker Secret，不能放入仓库或前端。提交 Worker 源码或发布 Pages 不会自动更新线上 Worker。

启用文档阅读方式保存时，确认线上 `/health` 返回 `capabilities.readingMode: true`；旧服务不支持该设置。接口和上传限制见 [Worker 接口约定](docs/worker-api.md)。
